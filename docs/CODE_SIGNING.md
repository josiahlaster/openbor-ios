# OpenBOR Build 6391 - iOS Code Signing & Distribution Guide

This document describes how to sign and deploy OpenBOR Build 6391 to native iOS devices via local sideloading or automated GitHub Actions CI.

---

## 1. Sideloading Unsigned Development IPAs (No Paid Apple Developer Account Needed)

If you do not have an Apple Developer account, you can install the unsigned `.ipa` generated by GitHub Actions or `scripts/build-ios.sh` using modern sideloading utilities:

### Method A: AltStore / Sideloadly (Windows & macOS)
1. Download `OpenBOR-v3.0-Build6391-iOS.ipa` from the GitHub Actions Artifacts section.
2. Launch **Sideloadly** or **AltStore** on your Windows PC or Mac.
3. Connect your iPhone / iPad via USB.
4. Drag and drop the `.ipa` file into Sideloadly.
5. Enter your free Apple ID credentials to resign with a 7-day personal certificate and install.

### Method B: TrollStore (iOS 14.0 - 16.6.1, CoreTrust bug)
* Install the `.ipa` directly in TrollStore without signing expiration or limits.

## 2. Automated Code Signing via GitHub Actions (Encrypted Secrets)

The GitHub Actions workflow (`.github/workflows/ios-build.yml`) automatically signs the IPA if repository secrets are configured.

### Required Secrets
Navigate to your GitHub Repository -> **Settings** -> **Secrets and variables** -> **Actions** -> **New repository secret**:

| Secret Name | Description | How to Obtain |
|---|---|---|
| `APPLE_CERTIFICATE_BASE64` | Base64-encoded `.p12` file containing your iOS Development or Distribution Certificate and private key. | Export from macOS Keychain Access (`Certificates` -> Right click -> `Export...`), then run `base64 -i cert.p12 -o cert.txt`. Copy contents. |
| `APPLE_CERTIFICATE_PASSWORD` | Password protecting the exported `.p12` file. | The password you entered during Keychain export. |
| `PROVISIONING_PROFILE_BASE64` | Base64-encoded `.mobileprovision` file matching your App ID (`org.openbor.engine` or custom). | Download from developer.apple.com -> `Certificates, Identifiers & Profiles`, then run `base64 -i profile.mobileprovision -o profile.txt`. |

### Security Boundaries
* Never hardcode certificates, `.p12` files, or passwords in Git repositories.
* The workflow creates a temporary, self-destructing macOS Keychain for each job that is wiped when the runner completes.
* If secrets are not present, the workflow automatically falls back to an **unsigned development build** that is ready for Sideloadly, AltStore, or TrollStore.
